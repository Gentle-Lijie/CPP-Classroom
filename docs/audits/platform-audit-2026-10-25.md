## 版本与证据边界

- 原平台审查使用 `.local/ui-audit-baseline` 中的 HEAD 隔离副本，预览端口 5180。工作区入场时已有五个文件的未完成修改；部分页面引用不存在的分页组件。继续修改前收到“先完整定位”的要求，所有实现工作随即暂停。
- 原版逐页截图不代表当前未完成修改已通过验收。`pnpm check` 已实际执行，当前工作区在 TypeScript 阶段失败：缺失 Pagination/usePagination、未注册 success/warning 按钮变体、notify 签名不匹配等。完整日志 `.local/ui-audit-check.log`。
- 静态审查记录 A01–A42、T01–T45、S01–S40 是原始发现，含重复根因、产品建议、待验证条件及中间修改缺陷；**不能将 127 条记录称为 127 个已复现 bug**。下表合并为 60 个处理主题，等级代表影响，证据列明确浏览器/源码/待验证。
- 浏览器检查覆盖 17 个 Vue view 的角色/路由变体、桌面 1440×900 和窄屏 390×844、关键只读弹窗及文档底部滚动。动态数据为空的情况不能算非空交互已验证。
- 没有重置真实密码、创建真实账号、执行学生程序或删除原数据。审查投屏只新增一个临时草稿快照，检查后撤销；恢复/入班成功和空数据故障复现使用明确标记的网络 mock。

## 优先阻断问题

1. 新增的教师批量重置补丁存在跨课堂账号接管路径，属于本轮中间补丁风险，必须先隔离并重新限定授权，不能直接交付（A01/X01）。
2. 原版全局裸学号自动匹配学生，不同教师同号异名会静默合并身份（A02）。
3. 教师示范与学生工作区异步请求、自动保存、切题未绑定实体，存在串题/覆盖修改的代码路径（S01–S08）。
4. 提交快照投屏把 submission ID 当 run ID，确定失败；草稿投屏契约也不完整（S10/S28）。
5. 恢复成功后返回登录会保留成功状态，登录表单消失，已用 mock201 和真实前端操作证实（A04）。
6. 无练习课堂缺少可靠空态；原版总览/学生详情直接解引用空题目；当前工作区则另外存在编译阻塞。
